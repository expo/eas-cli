# Guest resource profiling

Set `EAS_DEVICE_RUN_GUEST_METRICS=1` in the device session's worker step environment to collect `guest-metrics.ndjson` alongside app metrics. The existing start/collect serve-sim metrics steps own its lifetime, including Simulator startup. This is opt-in while overhead and retention are evaluated.

The file contains metadata, one sample per second (best effort), and a terminal health record. Each sample includes aggregate busy core equivalents (1 = one fully busy vCPU), cumulative process CPU and interval deltas, PID/start-time identity, parent PID, RSS, raw `vm_stat`, swap and memory-pressure counters. IOAccelerator registry data is recorded every five samples when exposed by the guest. Executable paths are included; command arguments and environment are not recorded. The file is private and capped at approximately 128 MiB. Commands time out after two seconds and errors remain visible in samples.

Check the terminal record, sample gaps, per-command errors and timestamps before interpreting a phase. A missing terminal record means incomplete collection. Failed process samples reset the delta baseline. Processes born or exited between samples cannot be fully attributed; residual core usage can be negative because process and aggregate counter boundaries differ. RSS contains shared pages and is not physical footprint. Free memory excludes reclaimable cache; interpret it with pressure, compression and swap. GPU allocations consume shared system memory and do not measure physical GPU or video encoder saturation. Physical host mapping, co-tenant contention, GPU/AVE utilization, process stacks and browser WebRTC statistics require separate collectors.

For experiments, record the exact collector commit and artifact hash, app/package versions, image and actual guest CPU/RAM. Capture cold startup separately, wait for a settled baseline, then alternate recording off/on several times on the same VM. Match actual resources before comparing VM sizes. Preserve phase timestamps and recording encoder logs alongside telemetry.

The Guest metrics artifact GitHub workflow compiles the standalone collector from the PR head and includes its source commit and checksum. A hosted experiment can load this module directly; that validates collector behavior on a hosted VM, while the worker upload integration still requires a worker containing this change.
